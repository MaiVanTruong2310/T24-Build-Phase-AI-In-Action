# ADR-004: Persistence và realtime cho Chat Takeover

**Ngày:** 2026-10-02  
**Trạng thái:** Accepted  
**Liên quan:** CHAT-TAKEOVER-001

## Bối cảnh

Màn hình `frontend/src/pages/ChatTakeover` hiện mô phỏng hàng đợi và tin nhắn bằng state cục bộ. Backend đã có chat archive theo `chat_conversations` và `chat_turns`, nhưng chưa có khái niệm case takeover, staff message hoặc claim độc quyền.

Chat patient tiếp tục dùng HTTP/SSE hiện có. Luồng staff cần persistence và realtime riêng để không làm thay đổi hợp đồng của `/chat` và `/chat/stream`.

## Quyết định

Mở rộng layered monolith hiện tại bằng các thành phần sau:

```text
Patient chat / Staff UI
        │ HTTP + WebSocket
        ▼
chat_takeover API router
        │
ChatTakeoverService
        ├── chat_takeover_cases
        ├── chat_takeover_messages
        └── chat_takeover_audit_events
        │
PostgreSQL (cùng database với chat archive)
```

### Persistence

- `chat_takeover_cases` đại diện cho một phiên takeover theo `session_id`.
- `chat_takeover_messages` lưu message của `patient`, `assistant`, `staff` và `system`.
- `chat_takeover_audit_events` lưu actor, event type và metadata tối thiểu.
- Claim dùng transaction và điều kiện `assigned_staff_id IS NULL` hoặc case đã hết lease; thất bại trả `409`.
- `client_message_id` unique theo case để đảm bảo idempotency.

### API contract MVP

| Method | Path | Quyền | Mục đích |
| --- | --- | --- | --- |
| `GET` | `/api/v1/staff/chat-takeover/cases` | staff | Queue và filter trạng thái |
| `GET` | `/api/v1/staff/chat-takeover/cases/{case_id}` | staff | Chi tiết case + history |
| `POST` | `/api/v1/staff/chat-takeover/cases/{case_id}/claim` | staff | Claim nguyên tử |
| `POST` | `/api/v1/staff/chat-takeover/cases/{case_id}/release` | staff | Trả case về queue |
| `POST` | `/api/v1/staff/chat-takeover/cases/{case_id}/resolve` | staff | Kết thúc takeover |
| `POST` | `/api/v1/staff/chat-takeover/cases/{case_id}/messages` | staff | Gửi message staff |
| `WS` | `/api/v1/staff/chat-takeover/ws/{session_id}` | authenticated patient | Realtime message/status for one session |
| `WS` | `/api/v1/staff/chat-takeover/ws/staff` | staff | Realtime queue/case updates |

Mọi mutation phải ghi DB thành công trước khi publish event. Event tối thiểu có `type`, `session_id`, `case_id`, `message` hoặc `case`, và `occurred_at`.

### Realtime

Tạo `ChatTakeoverConnectionManager` theo `session_id`, tách khỏi notification manager theo `user_id`. Đây là in-process MVP; cần thay bằng broker dùng chung trước khi chạy nhiều worker.

### An toàn

- Staff API bắt buộc `require_staff`.
- Patient WebSocket chỉ được subscribe session thuộc user hiện tại.
- Staff chỉ thấy clinical context tối thiểu cần cho ca đang xử lý.
- Không log nội dung message hoặc PII đầy đủ; audit chỉ lưu actor, event và ID.
- Case `resolved` không cho gửi message mới.

## Các phương án không chọn

### Chỉ dùng notification WebSocket hiện có

Không chọn vì notification manager fan-out theo user, không biểu diễn được room theo session và dễ trộn event nghiệp vụ với notification.

### Chỉ dùng `chat_turns` để lưu staff message

Không chọn vì schema turn hiện tại mô hình hóa một request patient và một assistant response; nhét nhiều staff message vào `assistant_text` làm mất author, thứ tự và audit.

### Dùng Redis ngay trong MVP

Không chọn vì repo chưa có Redis dependency/deployment. In-process manager đủ cho single-process/dev; rủi ro scale được ghi rõ để xử lý ở phase sau.

## Hệ quả

- Thêm migration và ba bảng nghiệp vụ mới.
- Có hai nguồn lịch sử cần hợp nhất khi đọc: turn cũ và staff messages.
- Cần test concurrency và reconnect, không chỉ test happy path.
- API patient hiện tại không bị breaking change.
